# 数字员工详情页重设计技术方案

## 实施状态

状态：已完成。

完成范围：

- 已重构数字员工详情页壳层、Hero、概览卡片和工作区导航。
- 已新增默认 `概览` Tab 和就绪检查。
- 已统一 Persona、人设文件编辑器、渠道绑定、会话历史、配置页的主要视觉风格。
- 已将配置页从 `Form` 调整为卡片式 section。
- 已新增会话搜索、绑定空状态、路径复制、刷新和更多操作。
- 已通过 `xcodebuild -project EZRWorker.xcodeproj -scheme EZRWorker -destination platform=macOS build` 编译验证。

## 背景

当前数字员工详情页由 `AgentWorkspaceView` 承载，已经具备角色定义、渠道绑定、会话历史和设置四类能力：

- `AgentWorkspaceView`：详情页壳层、员工头部、Tab 切换。
- `AgentPersonaEditorView`：persona 文件编辑器。
- `AgentBindingsView`：单个员工的渠道绑定管理。
- `AgentSessionsView`：会话历史浏览。
- `AgentSettingsView`：模型、Skills、路径与元信息配置。

现有问题主要不在数据能力，而在信息架构和视觉一致性：

1. 首屏偏“工程编辑器”，用户进入后先看到的是文件/Tab，而不是员工状态和下一步动作。
2. 字号层级和 `模型`、`消息渠道`、`设置` 页面不统一，详情页整体显得更旧。
3. 顶部员工信息较弱，只展示名称、描述、少量绑定 tag，无法快速判断该员工是否就绪。
4. `设置` 使用默认 `Form`，和当前主线页面的卡片式 section 风格割裂。
5. Persona、Bindings、Sessions、Settings 各自局部工具栏风格不一致。

这里说“首屏先回答问题”，不是指页面真的展示问答，而是指页面第一屏要让用户立刻获得三个关键判断：

- 这个数字员工是谁？
- 当前能不能正常工作？
- 我现在最应该做什么？

## 设计目标

1. 将详情页从“文件编辑入口”升级为“数字员工控制台”。
2. 字号、间距、卡片风格与 `PageHeroHeader`、设置页、模型页、渠道页保持一致。
3. 保留现有数据层和业务能力，优先做 UI/交互重排，降低风险。
4. 让高频动作更顺手：编辑信息、刷新状态、绑定渠道、选择模型、保存 persona。
5. 让异常状态更明显：Gateway 未连接、未绑定渠道、未设置模型、persona 文件缺失、未保存内容。

## 范围

### 本次包含

- 重构 `AgentWorkspaceView` 的页面结构。
- 新增详情页概览区域和概览 Tab。
- 统一详情页局部字体、卡片、按钮、状态徽章风格。
- 调整 Persona / Bindings / Sessions / Settings 的视觉容器和空状态。
- 保留现有 `AgentStore`、`AgentWorkspaceManager`、`GatewayService` 等服务接口。

### 本次不包含

- 不重做 `AgentStore` 数据模型。
- 不新增 Gateway API。
- 不重做创建员工向导。
- 不实现复杂会话摘要、AI 总结、persona 历史回滚等增强能力。
- 不改动 OpenClaw 配置文件结构。

## 现有页面对齐基准

详情页应对齐这些页面的视觉语言：

- `PageHeroHeader`
  - 标题：36pt bold。
  - 副标题：22pt regular，secondary。
- `AppSettingsView`
  - 页面 padding：水平 28、顶部 24、底部 28。
  - 卡片：`controlBackgroundColor`、圆角 22-24、1px 低透明描边、轻阴影。
  - 局部字号：标题 20、正文 16、说明 15、meta 14、badge 13。
- `ModelConfigView`
  - Section card 承载复杂配置。
  - 顶部 Hero + 右侧主操作。
- `ChannelView`
  - 渠道/绑定类信息以卡片或行内状态展示。
  - 状态 badge 使用颜色轻提示，不做大面积高饱和背景。

### Tab 调整

当前 Tab：

- 角色定义
- 渠道绑定

### 颜色与材质

- 页面背景：`Color(nsColor: .windowBackgroundColor)`。
- 主卡片背景：`Color(nsColor: .controlBackgroundColor)`。
- 卡片内弱块背景：`Color(nsColor: .windowBackgroundColor).opacity(0.72)` 或 `Color.secondary.opacity(0.06)`。
- 描边：`Color.black.opacity(0.08)` 或 `Color.primary.opacity(0.08)`。
- 状态色：
  - 正常：green。
  - 需要配置：orange。
  - 异常：red。
  - 未配置/未知：secondary。

## 功能设计

### 1. Hero Header

展示内容：

- emoji，空值时 fallback 为 `🤖`。
- 员工名称。
- 分类 badge。
- 状态 badge。
- 描述。
- 技能标签最多 3 个。
- 绑定渠道图标最多 4 个，超出显示 `+N`。

右侧操作：

- `编辑信息`：打开现有 `AgentEditorView`。
- `刷新`：调用 `store.refreshRuntimeState()`。
- `更多`：
  - 打开 Workspace 路径。
  - 复制 Agent ID。
  - 删除员工（非 `main`，仍需二次确认）。

### 2. Overview Cards

四张概览卡片，横向自适应：

1. 模型
   - 有 `preferredModel`：显示模型名。
   - 没有：显示“使用全局默认”。
   - Gateway 未连接时显示橙色提示。

2. 渠道绑定
   - 显示绑定数。
   - 无绑定时提示“未绑定渠道”。
   - 点击可切到 `渠道` Tab。

3. 会话
   - 显示 `sessionCount`。
   - 显示最近活跃时间。
   - 点击可切到 `会话` Tab。

4. Workspace
   - 显示路径摘要。
   - 显示 persona 是否可读取。
   - 点击可切到 `人设文件` Tab。

### 3. 概览 Tab

`概览` Tab 用于展示就绪检查和快捷动作。

就绪检查项：

- Gateway 连接状态。
- 模型配置状态。
- 渠道绑定状态。
- Persona 文件状态。
- Workspace 路径状态。

每项结构：

- 左侧 icon + 标题 + 说明。
- 右侧状态 badge。
- 可选快捷按钮。

快捷动作示例：

- Gateway 未连接：显示“等待 Gateway 连接”，按钮禁用。
- 未绑定渠道：按钮“添加绑定”，切换到渠道 Tab 并打开添加 sheet。
- 未设置员工模型：按钮“选择模型”，切换到配置 Tab。
- Persona 文件缺失：按钮“编辑人设”，切换到人设文件 Tab。

### 4. 人设文件 Tab

保留现有分栏结构：

- 左侧：`PersonaFile.allCases` 文件列表。
- 右侧：当前文件编辑器。

调整点：

- 左侧文件项字号从 12/10 调整到 14/13，提升可读性。
- 右侧顶部工具栏统一为：
  - 文件名。
  - 文件说明。
  - 未保存状态。
  - 保存按钮。
  - 放弃更改按钮。
- 保存按钮使用系统 bordered/prominent 风格。
- `TextEditor` 保留 monospaced body。
- 错误态和缺失文件态使用 `ContentUnavailableView`。

### 5. 渠道 Tab

在现有 `AgentBindingsView` 基础上重排：

- 顶部 Section header：标题、说明、添加绑定按钮。
- 有绑定时使用卡片/行列表：
  - 渠道图标。
  - 渠道名称。
  - 绑定摘要。
  - 绑定范围 badge（私聊/群/账号等，按现有字段推断）。
  - 删除按钮。
- 无绑定时：
  - `ContentUnavailableView`。
  - 主按钮“添加绑定”。

行为仍复用现有 `AddBindingSheet` 和 `store.addBinding/removeBinding`。

### 6. 会话 Tab

保留 `HSplitView`，增强顶部工具栏：

- 标题。
- 会话数量。
- 刷新按钮。
- 可选搜索框，先做本地按文件名过滤。

列表项：

- 文件名：13pt monospaced。
- 文件大小：12pt secondary。
- 后续若 `FileEntry` 有时间字段，可增加时间。

详情区：

- 未选择：`ContentUnavailableView`。
- 加载中：`ProgressView`。
- 错误：`ContentUnavailableView`。
- 内容：`Text` monospaced，支持 text selection。

### 7. 配置 Tab

将默认 `Form` 改为 card section：

1. 模型配置
   - 首选模型 Picker。
   - Gateway 未连接提示。
   - 保存状态/错误提示。

2. Skills 允许列表
   - TextField 或 TextEditor。
   - 保存按钮。
   - 说明文字“留空继承全局”。

3. 路径与元信息
   - Agent ID。
   - Workspace 路径。
   - Bindings 数。
   - Sessions 数。
   - 最近活跃。
   - 路径支持点击查看完整路径/复制。

4. 危险操作
   - 非 `main` 员工展示删除入口。
   - 二次确认。

## 交互细节

### 刷新

详情页右上角刷新调用：

```swift
Task {
    await store.refreshRuntimeState()
}
```

刷新时按钮展示小型 loading 或禁用，避免重复点击。

### Tab 切换

Overview card 和 readiness row 可通过 closure 修改 `selectedTab`：

```swift
selectedTab = .bindings
```

如果需要打开添加绑定 sheet，后续可以给 `AgentBindingsView` 增加可绑定的外部触发状态；第一版只切换 Tab。

### 保存状态

Persona 保存沿用现有 dirty 判断：

```swift
(editorContents[file] ?? "") != (savedContents[file] ?? "")
```

新增“放弃更改”：

```swift
editorContents[selectedFile] = savedContents[selectedFile] ?? ""
```

### 路径展示

路径默认显示 `abbreviatingWithTildeInPath`。完整路径通过 popover 或复制按钮提供。

## 风险与处理

1. `ScrollView` 与 `HSplitView` 嵌套可能影响高度。
   - 处理：详情页外层不强制所有 Tab 都在同一个 ScrollView 中。对于 Persona/Sessions 使用 `frame(maxHeight: .infinity)` 的工作区容器。

2. `AgentSettingsView` 目前是私有组件，移动删除入口可能引入重复逻辑。
   - 处理：第一版只改变视觉容器，不改变删除/保存业务逻辑。

3. 字号变大后小窗口可能拥挤。
   - 处理：Hero 使用 `ViewThatFits` 或右侧操作换行；overview cards 使用 adaptive grid。

4. 绑定添加 sheet 由内部状态控制，概览快捷动作无法直接打开。
   - 处理：第一版快捷动作只跳转到渠道 Tab；第二版再做外部触发。

5. `Skills 允许列表` 当前只编辑本地 state，没有完整保存逻辑。
   - 处理：本次要么补保存到 `Agent.skills`/gateway config，要么暂时明确展示为“技能标签”。实现前需确认当前 openclaw 配置映射。

## 验收标准

1. 详情页首屏包含员工身份、状态、主要动作和 4 个概览卡片。
2. 默认进入详情页时选中 `概览`。
3. 字体大小与设置/模型/渠道页面一致，不再出现大量 10-12pt 作为主体信息。
4. Persona、渠道、会话、配置四个区域视觉风格统一。
5. Gateway 断连、未绑定渠道、无会话、文件缺失等状态都有清晰提示。
6. 现有功能不回退：
   - 能编辑员工信息。
   - 能保存 persona 文件。
   - 能添加/删除渠道绑定。
   - 能浏览会话。
   - 能修改首选模型。
7. 编译通过，无明显布局重叠或截断。

## 建议优先级

优先实现：

1. Hero + overview cards + overview Tab。
2. Persona 编辑器视觉统一。
3. Settings 卡片化。

然后实现：

4. Bindings 空状态和列表卡片化。
5. Sessions 搜索与数量展示。
6. 更多菜单、路径复制、删除入口迁移。

这样可以先让详情页整体气质和主线页面统一，再逐步打磨局部体验。
